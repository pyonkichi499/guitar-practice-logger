# ロードマップ

一度に全部を作らず、毎日の手作業を減らせるところから段階的に作る。状態は ✅ 済み、🚧 一部済み、⬜ 未着手。

## 進める順番と理由

```text
Phase 1 ✅ → Phase 2-A 🚧 → Phase 2-C ⬜ → Phase 2-B ⬜ → Phase 3 ⬜
```

- **Phase 1 の取り込みを最初に作った理由**: DAW から既定の名前で書き出すと、前日のファイルを上書きしてしまう。録音を始める時点で取り込みの仕組みが必要だった。
- **2-A を 2-B より先にする理由**: 毎日の手作業で一番重いのは、動画化とアップロード。録音は DAW のままでも困らない。
- **2-C（GCP）を 2-B より先にする理由**: 2-A で作った処理の本体をそのまま移せるので、作りたてのうちに移すほうが楽。
- Phase 1 の間に取り込んだ分は、2-A ができたらまとめて公開する（2-A のテストデータにもなる）。

## Phase 1: DAW で録音し、取り込む ✅

- **手作業**: Cakewalk で各メニューを録音し、曲フォルダに書き出す。`gpl intake` で BPM を入力して確定する。
- **自動**: WAV にメタデータを書き込み、日付・曲・BPM 入りの名前でアーカイブへ移し、SQLite に記録する。
- **残る手間**: 書き出し操作、`intake` の実行、BPM の入力。
- **要確認**: Cakewalk Next で、曲ごとのプロジェクトに書き出し先を固定できるか。

## Phase 2-A: 後処理の自動化 🚧

`gpl publish`（仮）で、取り込み済みでまだ公開していないテイクをまとめて処理する。

- ✅ 静止画（日付・曲名・BPM）と WAV を合わせて、ffmpeg で MP4 にする（`intake` の中で行う。作り直しは `gpl render`）
- YouTube に公開でアップロードする（音はギターとクリックのみ）
- WAV を Drive API で GDrive に保存する
- 動画 ID と Drive のファイル ID を SQLite に記録し、二重アップロードを防ぐ

**手間の変化**: 動画化とアップロードの手作業がなくなり、`intake` の後に `publish` を実行するだけになる。

**着手時に決めること**: OAuth 同意画面のモード（[設計判断](design-decisions.md#保留事項)を参照）。最初に 1 本、公開アップロードが通るか試す。

## Phase 2-C: GCP への移行 ⬜

目的は GCP を学ぶこと（手間を減らすためではない）。

- 2-A の処理の本体を GCS と Cloud Run に移す
- 練習の記録を BigQuery に入れ、Looker Studio で可視化する（BPM の推移など）

**手間の変化**: WAV を置いたら PC を切ってよくなる。

## Phase 2-B: 録音のスクリプト化（DAW をやめる） ⬜

- スクリプトで曲を選んで録音する。クリックはスクリプトが鳴らして合成する
- 書き出し操作と曲フォルダが不要になる
- 公開版はギターだけ、という方針は変わらない。バッキングと混ぜた版は必要になったら作る

**着手時に決めること**: 実行環境（録音は Windows 側でしか安定しない。[調査結果](research.md)を参照）、録音の遅延の補正。

## Phase 3: GUI ⬜

- 曲を選び、BPM を入力して、録音から公開までをボタン操作で行う
- 今の CLI の処理を、そのまま GUI から呼び出す
